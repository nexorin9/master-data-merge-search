# 视觉目标卡 · 主数据归并检索系统（P1）

> 本卡由 Phase 1 产出，Phase 4 **Task 1** 创建 `docs/concepts/` 后把本卡原文落盘为 `docs/concepts/visual-target-p1.md`，README「概念 / 实测对照」小节以本卡为左侧目标、实测截图为右侧证据。**当前运行环境不具备图像生成能力**，故**只保留结构化视觉目标卡，不伪造任何概念图、不放占位图**。

## 7.1 三个状态

1. **起始态（托盘常驻 · 未开窗）**：屏幕右下角只有一个托盘图标（深蓝圆点），**不弹窗、不抢屏**；托盘右键菜单三项——「打开评审台」「待确认 N 条」「检查新批次」。此时产品已在后台按 `MDM_BASE_URL` 轮询候选池；有新批次到达时图标旁出现数字角标（N）。
2. **首个可用瞬间（拖入候选表后 3 秒内）**：主窗口中央出现**候选卡片流**，每张卡片自上而下三段——顶行左侧一枚三态标签（`新建` / `并入` / `存疑`），顶行右侧「证据 2 条 · 追问」；中段**左右并排**两列字段（左＝候选名称 / 规格 / 单位 / 医保码，右＝已有主数据对应字段值，命中两行用同色下划线连起）；底行一行等宽小字「主数据 #<code> · 记录 <record_id>」。卡片逐条淡入（每条 ≤150ms），**全程不出现进度弹窗**。
3. **成形态（跑完一批并写回后）**：顶栏三枚计数（待评 12 / 已建议 8 / 存疑 3）；中间为可滚动候选列表，每行左缘一列三态色条；右侧常驻**会话栏**显示同一候选的历史问答（「为什么不并到 <另一条>」→ 回答 → 出处链接）；右下角「写回主数据平台」按钮点开**确认框**，逐条列出将写入的建议（候选 id / 动作 / 目标编码 / 幂等键前 8 位），确认后逐条显示回执行（成功 / 跳过：已存在同哈希建议 / 失败：原因），失败行**显式红色报错**，不静默改数据。

## 7.2 画面类型

**桌面窗口**（Electron 主进程 + preload + 渲染层，托盘常驻 + 主窗口），与编排锁定的交付形态「桌面常驻小工具」一致。**不是**终端会话、**不是**浏览器页面、**不是**服务运行日志、**不是**导出的报告页；命令行只作为运维与排障通道。

## 7.3 视觉语言

- **配色**：窗口底色 `#F7F8FA`；卡片底 `#FFFFFF`、卡描边 `#E3E6EB`；正文 `#1F2933`、次要文字 `#6B7280`；主色（`并入`）`#1F6FEB`；`新建`绿 `#2E7D32`；`存疑`琥珀 `#B26A00`；证据引用下划线 `#1F6FEB`；回执成功 `#2E7D32`、失败 `#C62828`。
- **字体族**：界面文字 `PingFang SC / Microsoft YaHei`；编码、字段值、幂等键等宽 `JetBrains Mono / Menlo`。
- **信息层级**：**最显眼 = 每条候选的三态标签 + 左右并排的命中字段对照**（居中主区，约占卡片 60% 视觉权重）；次要 = 证据条数与追问按钮（卡片右上）；再次 = 顶栏计数与托盘角标（弱化，不抢主区）；会话栏靠右、次要字重。
- **留白密度**：中等偏松——卡片内边距 12–16px，字段对照两列各占 40% 定宽、字段行高 24px；**不用密集表格**，一屏放 3–4 张卡片。

## 7.4 必须可达的约束（只允许当前依赖真能做出来的元素）

- 托盘角标计数、卡片三态色、并排字段对照、右侧会话栏、确认框与逐条回执行：**全部可由 Electron（tray + BrowserWindow + preload IPC）+ 本机工作区（JSON / SQLite）+ 单一 ModelGateway 调用实现**，不依赖特殊硬件。
- **明确不画**：实时曲线 / 动画图表、WebGL 3D、地图、热力图、语音输入动效、网页式搜索框——现有依赖做不出来，或会把评审台变成监控大屏，与"一个岗位时刻"不符。
- **诚实标注**：本卡为**目标**；Phase 4 的 `docs/screenshots/` 为**实测**。README 对照小节须写明两侧差异，**不得**声称两者完全一致。
